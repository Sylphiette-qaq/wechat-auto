## Context

当前项目通过 `scripts/atspi_probe.py` 读取微信 4.1.1.8 的 AT-SPI 控件树，并由 Go CLI 以 JSONL 转发或归一化消息事件。发送能力尚未实现；本变更只增加一个一次性 UI 发送流程，用户负责登录微信并打开目标会话，自动化程序负责把一段 stdin 文本发送到当前会话。

实现必须继续停留在 UI 自动化边界：不读取微信数据库、进程内存或协议，不使用逆向、Hook、ptrace 或 OCR。实际输入和发送使用 X11 键盘事件，AT-SPI 仅用于识别当前窗口、定位输入框、设置焦点和读取发送后的可见状态。

## Goals / Non-Goals

**Goals:**

- 增加 `wechat-cli --mode send` 和 `scripts/wechat.sh send`。
- 只向当前已经打开的群聊或私聊发送一条普通文本消息。
- 从 stdin 原样读取文本；空输入和纯空白输入拒绝，换行不拆分消息。
- 激活唯一微信窗口，唯一定位消息输入框并确认 `focused` 后才继续。
- 使用 `xclip` 写入 X11 `CLIPBOARD`，使用 `xdotool` 执行 `Ctrl+V` 和发送快捷键。
- 发送快捷键固定使用已验证可行的 `Enter`；每次调用只发送一次且不自动重试。
- 在粘贴后校验输入框内容，在发送后验证输入框清空并尽量观察消息回显。
- 发送过程串行化，结束后尽力恢复原文本剪贴板，并输出结构化结果。

**Non-Goals:**

- 不搜索、切换或按名称选择会话。
- 不支持批量发送、图片、文件、引用、语音或其他复杂消息类型。
- 不考虑自动发送期间的用户手工输入竞争。
- 不实现自动回复策略、LLM、限流、审计或分布式锁。
- 不保证恢复非文本或富文本剪贴板格式。

## Decisions

### 1. 发送边界保持在当前打开会话

发送器只接受当前 UI 状态，不增加目标聊天搜索流程。发送前通过 AT-SPI 标题和现有 Chats/Messages 上下文确认会话存在；标题不可读、无法匹配或输入框不唯一时直接失败。

备选方案是用微信搜索框按名称切换会话，但会引入搜索结果误匹配和额外焦点状态，不属于第一版。

### 2. 分层保持 Go 编排、Python UI 操作

Go CLI 负责读取 stdin、校验发送参数、取得发送锁、启动探针、转发结果和设置退出码。Python 探针负责 AT-SPI 远程对象访问以及 `xclip`/`xdotool` 子进程调用。发送器不把 X11 或 AT-SPI API 泄露到领域事件模型。

备选方案是新增 Go X11 依赖；这会破坏当前无第三方依赖的最小结构，且不利于复用已有 Python AT-SPI 代码。

### 3. 通过 AT-SPI 唯一定位并锁定输入框

探针在当前微信应用树中寻找唯一可编辑消息输入节点，优先使用输入框名称和可编辑状态，并调用焦点能力后再次读取 focused 状态。零个或多个候选均失败，不使用盲目 Tab 作为兜底。

### 4. 剪贴板粘贴替代逐字符输入

发送文本先写入 X11 `CLIPBOARD`，再由 `xdotool key ctrl+v` 粘贴。这样避免逐字符模拟中文 Unicode 的不稳定性。粘贴后读取输入框正文，必须与 stdin 内容完全一致才发送。

### 5. 发送快捷键可配置且只执行一次

发送快捷键固定为 `Enter`。探针只执行一次该快捷键，不在失败后尝试其他快捷键，避免重复发送。

### 6. 结果验证和失败语义

发送前验证粘贴结果；发送后等待输入框清空，并尝试在 Messages 列表发现相同正文。输入框清空作为最低成功证据，消息回显作为增强证据，结果中区分验证级别。超时或无法确认时返回非零退出码，不重试。

### 7. 发送串行化与剪贴板恢复

在容器内使用一个简单文件锁保护发送临界区，避免多个 CLI 进程交叉覆盖剪贴板或键盘事件。进入临界区前读取原文本 CLIPBOARD，完成粘贴/发送后尽力恢复；非文本剪贴板只做 best-effort。

## Risks / Trade-offs

- [微信输入框名称或 AT-SPI 焦点 API 在不同状态下变化] → 使用唯一候选规则、focused 二次校验，并输出节点路径诊断。
- [X11 键盘事件被窗口忽略或窗口激活竞态] → 显式激活唯一微信窗口，按阶段轮询可见状态，失败不重试。
- [发送快捷键与微信设置不一致] → 仅采用已在当前微信实例验证成功的 Enter。
- [消息回显暂时不可读] → 输入框清空作为最低证据并标记验证级别，不把回显缺失当成可重试信号。
- [xclip 只保证文本剪贴板恢复] → 记录恢复结果，非文本格式不作强保证。
- [多个发送进程同时运行] → 文件锁串行化，锁竞争直接返回 `send_busy`。

## Migration Plan

1. 在 Docker 镜像中安装 `xclip` 和 `xdotool`。
2. 增加 Python send 流程、Go `send` 模式和 `wechat.sh send` 包装。
3. 为参数校验、剪贴板命令构造、结果解析和锁行为增加宿主机可运行的单测。
4. 在 noVNC 中登录微信并打开群聊，使用 stdin 发送中文文本，验证粘贴、发送和回读。
5. 若发送验证失败，保留诊断和控件树快照；回滚时移除 send 入口，不影响 observe/tree。

## Open Questions

- 微信 4.1.1.8 当前实例已验证使用 Enter；不再支持 Ctrl+Enter 分支。
- 微信当前输入框是否暴露完整可读正文，需要在 Docker 图形环境中验收；代码不得因读取失败而改用其他技术路径。
